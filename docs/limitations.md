# Limitations

What ATLAS does not do, has not validated, or only simulates.

## Data and intelligence

- **All data in the repository is synthetic.** Every demo record is labelled `SYNTHETIC_DEMO` and named `DEMO ...`;
  the UI shows a banner where scores are computed from synthetic evidence. No model has been evaluated on real
  data, so no accuracy, calibration or business-impact claim is made.
- **Supplier risk is a rule-based indicator** (methodology `rm-1`), not a probability and not machine learning.
- **Forecasting** uses classical statistical models (naive, seasonal naive, ETS family, ARIMA-like, Croston-type)
  implemented in pure Python, selected by rolling-origin validation. No deep learning.
- **Lead time / late delivery** uses median and ridge regression, base-rate and logistic models in pure Python.
  SHAP, LIME and causal explanations are not supported.
- **Cascading impact** is structural reachability through recorded relationships, not a predicted loss.
- **Scenarios** are deterministic what-if simulations of user-defined events; they are never shown as real events.
- **Optimisation** is exact only within stated bounds (small instances, enumerated candidates); otherwise the
  result is labelled (`BOUND_EXCEEDED`, heuristic or infeasible) rather than presented as optimal.

## Platform

- **SQLite by default, PostgreSQL 16 tested locally.** The migrations and the backend suite pass on PostgreSQL 16.2
  (SQLite-specific tests excepted, see [`testing.md`](testing.md)), but no deployment has run on it. On SQLite there is
  one writer at a time: the load test measured about 22 synchronous risk assessments per second regardless of
  concurrency, and writers that wait longer than the busy timeout get `503` with `Retry-After`
  ([`performance/LOAD_TEST.md`](performance/LOAD_TEST.md)).
- **One API process measured.** Read throughput was about 105-150 requests per second on one process, falling slowly
  as concurrency rises. Several processes or hosts have not been measured.
- **Organisations share one database.** All data is separated by organisation at the query layer
  ([`security/TENANT_ISOLATION.md`](security/TENANT_ISOLATION.md)). Record ids are global integers, so totals can be
  inferred. There is no per-tenant encryption or data residency.
- **No real third-party integration.** Connectors: a synthetic sandbox and a generic REST/JSON connector tested
  with a fake transport. Named ERP/WMS/TMS vendors are extension points that refuse creation.
- **No external paging.** Alerts are generated by on-demand evaluation or the in-process timer; notifications are
  in-app or signed webhooks.
- **Backups** are an online-backup script and a tested restore; no schedule, off-site copy or point-in-time recovery.

## Verification

- **Never run:** Docker images, Compose, the CI workflow, any hosted deployment.
- **Load testing:** one machine with client and server together; no soak test or multi-host test.
- **Security:** no independent assessment, penetration test or certification.
- **Accessibility:** automated axe-core scans find no WCAG 2.1 A/AA violations on any page. Automated rules catch
  only part of the problems, and there has been no audit with assistive technology or disabled users.
